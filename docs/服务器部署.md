# 服务器部署与同步

生产站点：`https://msg.shifuf.com`，管理入口：`/admin`。项目目录固定为 `/www/wwwroot/msg`，Compose 项目名为 `msg`，Web 沿用 `8085` 端口。宿主机已有 Nginx HTTPS 反代到该端口。

运行依赖由 Docker 镜像提供：Node 22、pnpm 9.15、PostgreSQL 16、Redis 7、Nginx。宿主机需要 Docker Engine 和 Compose 插件。API、数据库、Redis 不映射公网端口。

## 配置与备份

生产 `.env`、数据库备份和部署记录留在服务器项目目录内，不提交 Git。`data/` 同时被 Git 和 Docker 构建上下文排除。建议保存以下配置：

```dotenv
APP_ENV=production
WEB_PORT=8085
ADMIN_PATH=/admin
SITE_URL=https://msg.shifuf.com
FORCE_RESET_ADMIN_PASSWORD=false
```

现有 `JWT_SECRET` 通过生产校验时予以保留；若仍使用占位密钥，必须替换为安全随机值，旧会话和依赖旧签名的链接会失效。独立设置随机 `TOTP_ENCRYPTION_KEY` 并备份。`ADMIN_PASSWORD` 是初始化配置，需为至少 12 字符的非示例强密码；普通 seed 不修改已有管理员密码，勿开启强制重置。

每次更新前在 `data/deploy/<时间>/` 保存 `.env`、源文件归档、`pg_dump -Fc` 数据库备份以及当前镜像 ID，并为 API/Web 旧镜像保留回滚标签。迁移后的数据库需要与对应代码版本一起恢复，不能只回退镜像。

## 旧版首次升级

2026 年 7 月旧服务器使用多条历史迁移，仓库已将初始化合并为 `20260719000000_init`。已有数据库不能直接重新执行初始化 SQL。

1. 在独立数据库中恢复生产备份，用 Prisma 比较现有数据库与该初始化版本对应的 schema。
2. 确认结构等价后，在副本执行 `prisma migrate resolve --applied 20260719000000_init`，再执行 `prisma migrate deploy`，检查数据、管理员密码哈希和新表。
3. 副本验证通过后，在维护窗口暂停 API/Web，重新备份正式数据库，再对正式库执行相同步骤。

本次旧库仅比基线多出 `EmailSuppress.updatedAt`、`SystemSetting.updatedAt` 两个默认值，不影响升级，保留这些默认值。首次登记只执行一次；新部署使用常规迁移即可。勿用 `db push` 替代迁移。

## 后续同步

本地执行 `pnpm check`，并为真实集成测试提供隔离 PostgreSQL/Redis 地址；检查通过后提交并推送 `origin/main`。服务器保留同一 Git 提交，以便核对版本：

```bash
cd /www/wwwroot/msg
# 当前服务器未安装宿主机 Git，使用已经构建的专用工具镜像。
gitmsg() {
  docker run --rm -v /www/wwwroot/msg:/www/wwwroot/msg \
    -w /www/wwwroot/msg msg-deploy-git:local \
    -c safe.directory=/www/wwwroot/msg "$@"
}
gitmsg fetch origin main
gitmsg merge --ff-only origin/main
docker compose -p msg build api web
# 完成备份后更新应用，保留数据库与 Redis 实例
docker compose -p msg up -d --no-deps api
docker compose -p msg up -d --no-deps web
curl --fail https://msg.shifuf.com/api/health/ready
gitmsg rev-parse HEAD
```

如果服务器直连 GitHub 失败，在本地生成 `git bundle create data/deploy/main.bundle main`，通过 SSH/SFTP 上传到服务器同一路径，然后在服务器执行 `gitmsg fetch /www/wwwroot/msg/data/deploy/main.bundle main`、`gitmsg merge --ff-only FETCH_HEAD`。用本地 `git ls-remote origin refs/heads/main` 与服务器 `gitmsg rev-parse HEAD` 比较，确认与 GitHub 一致。此方式不需要在服务器保存 GitHub 令牌。

应用启动入口自动运行迁移和 seed。更新后检查首页、登录、鉴权接口、数据库、Redis 和发送 worker；保留原有账号、渠道、项目与消息。渠道适配器随 API 镜像安装，第三方渠道的连通性需使用对应账号配置验证。
