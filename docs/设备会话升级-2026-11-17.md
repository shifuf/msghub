- 迁移可与旧 API 并存。回滚应用镜像时保留新表即可，不要回删用户回复。

## 接口

- 新 JPush extras 保留 `messageId`、`readToken`，增加 `conversationId`（原始 MessageLog ID）、`conversationToken`。管理员回复使用同一 messageId/conversationId/token，并增加 `replyId`。
- `POST /api/public/messages/conversation`：`{messageId,token}`。
- `POST /api/public/messages/reply`：`{messageId,token,content,clientId}`。
- `GET /api/messages/:id/conversation`、`POST /api/messages/:id/reply` 需要管理员 JWT；同时提供现有后台路径 `/api/admin/messages/:id/conversation` 与 `/api/admin/messages/:id/reply`。
- 管理员回复 body 为 `{content,clientId}`。clientId 必须是 UUID；同一消息/作者/UUID 的重试返回原回复，内容变更返回 409。客户端应先保存 UUID，再发 HTTP，超时后继续复用。
- content trim 后 1–4000 字符。对端读取只标记本次返回的最近 100 条中的对端回复。按时间升序展示，title/content 始终是字符串。
- 会话 data：`{messageId,title,content,replies,canReply}`。reply：`{id,author,content,createdAt,readAt,clientId,deliveryStatus,deliveryError}`。
- `deliveryStatus`：设备回复 `STORED`；管理员回复 `PENDING` / `ACCEPTED` / `FAILED` / `UNCERTAIN`。`ACCEPTED` 只表示推送请求被服务商接受；失败回复仍保存在会话，设备前台拉取可见。中断超过两分钟的 PENDING 在后续读取时标记 UNCERTAIN，不自动重推。
- 公共读取每 IP 每分钟 60 次，回复 20 次，仍使用应用已有共享 Redis 限流。错误保持现有 `{success:false,error:{code,message},data:null}` 格式；成功保持 `{success:true,data,error:null}`。

## 安全与兼容

- 会话 token 使用独立 HMAC 域 `conversation:v1:`，readToken 不具备阅读/回复权限。token 不出现在查询字符串、接口响应或持久化消息审计 extra；推送发送时生成。现有出站客户端禁止跟随重定向。
- 发送时快照原 audience 和 appKey。后续管理员回复、原通知重发、队列执行保持原目标；渠道切换到其他 JPush 应用时阻止外发。不会替换用户的 RID 配置。
- 已送达旧通知没有会话凭证，后台和 App 明确提示旧通知不支持聊天。升级后新发（包括渠道测试、项目模拟发送）通知可回复；原本尚未投递的旧队列任务在新 worker 实际发送时补齐凭证。
- 别名、多 RID 与 all 的通知是整条通知共享的会话能力，收到同一通知的设备共享该会话；部署不将广播通知改为逐设备私聊。需要私密一对一会话应使用单 RID 目标。
- Web 详情自动每 10 秒读取；隐藏标签页/关闭详情停止轮询。失败草稿与 UUID 存于该浏览器标签页 sessionStorage，关闭详情或刷新可恢复；未确认提交先重试同一条，避免重复推送。
