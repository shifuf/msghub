# 消息与浏览器通知修复验收记录

本次将此前直接部署、尚未提交的设备会话功能与新的通知可靠性修复整合到同一个 `main`。Android 工程原路径为 `F:\浏览器\BrowserShell`，GitHub 中同步保存于 `clients/browsershell/`，逐文件散列见该目录的 `source-manifest.json`。

## 修复内容

- 设备管理、运行维护及会话收件箱注册到 API、网页路由和管理菜单。配对码绑定所选极光渠道，十分钟有效且只能使用一次；并发配对、撤销、RID 轮换受同应用事务锁保护。
- 发送链路统一产生消息与目标设备绑定的限时回执签名，覆盖同步、队列、渠道测试、备用渠道及失败告警。签名只在发送时生成，不保存到消息日志或队列。多设备回执还需对应已配对设备凭据；过大或无法枚举的受众明确显示回执不可用。
- 历史查询区分极光受理、应用到达、通知栏显示与用户已读，并显示受众数与回执数。单设备筛选只使用该设备的证据。心跳按事件触发，较久没有报告显示“状态待刷新”，不能据此判断离线。
- 会话收件箱支持回复幂等、失败及不确定送达状态、分页、关闭/重开，以及 SSE 重连和 HTTP 补查；清理记录时保护活跃会话及尚未确定送达的回复。
- 定时任务增加时区与执行历史。确定失败的周期任务可继续后续周期；不确定送达不自动重发。
- 运维页面显示构建提交、迁移、服务就绪状态与备份任务。独立 runner 加密备份 PostgreSQL、Redis 和部署配置，并在自身临时数据库真实恢复验证。API 不能写归档，也不挂载备份私钥或 Docker socket。
- 真实镜像验证发现并修复了 PostgreSQL socket 路径超长、Redis 尚未加载 RDB 就进行校验、数据库部分启动后遗漏停止，以及忽略进程停止失败仍标记通过的问题。生产验收还复现并修复了无密码 Redis 被传入空 AUTH 导致快照失败的环境差异，并补上有认证和无认证两种真实镜像场景。
- BrowserShell 2.2.3/code36 提前初始化极光，增加设备关联及权限入口、AndroidKeyStore 加密凭据、持久化回执重试与网络恢复。只有观察到系统中对应的活动通知 ID 才报告“已显示”，并尊重应用暂停推送的选择。

## 安装与关联

1. 从原统一文件平台更新到 BrowserShell 2.2.3。固定下载身份和清单地址继续沿用，消息平台不增加 APK 下载入口。
2. 在 Android 系统中允许该应用通知，并在浏览器“通知权限”中检查通知渠道；需要后台即时通知时，按手机系统设置允许应用在后台运行。
3. 在消息后台“设备管理”选择实际发送所用的极光渠道，生成一次性配对码，在浏览器“关联消息设备”中输入。
4. 页面出现最近设备报告后，再从实际业务消息的历史中核对“到达/显示/已读”阶段。极光受理或构建成功不能证明手机已经显示通知。

本轮没有可运行的测试手机，因此尚无新版安装后在目标手机上实际配对、收到推送或显示通知栏的验收证据。服务端与 APK 发布验证须分别核对运行提交、公开下载 SHA-256、版本及原签名；不能据此替代真机验收。
