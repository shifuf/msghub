# MsgHub 与 BrowserShell 修复交付

本次在 `fix/comprehensive-hardening-20261117` 分支修改消息平台，同时修改 `F:\浏览器\BrowserShell` 的通知回执相关源码。原审查报告是修复前基线；本文描述修复后的行为。未部署线上、未重置现有管理员、未向第三方发送真实通知。

## 升级顺序

1. 先对现有 PostgreSQL 做完整备份，保留当前镜像与配置。配置导出不能替代数据库灾备。
2. 使用 Node 22.22+；执行 `pnpm install --frozen-lockfile`、`pnpm db:generate`。生产容器使用 pnpm 9.15 和锁文件，API 使用 TypeScript 直接编译，移除不需要的 Nest CLI 依赖链。
3. 设置随机 `JWT_SECRET`（至少32字符）和非示例初始化密码（至少12字符）。已有账号不会因普通 seed 改密；不要无意开启 `FORCE_RESET_ADMIN_PASSWORD`。生产初始化失败会阻止启动。
4. 建议设置独立随机 `TOTP_ENCRYPTION_KEY` 并安全备份。未设置时从 JWT_SECRET 派生密钥，轮换 JWT_SECRET 将使已有 TOTP 密文无法解密。TOTP 不包含在配置迁移包内。
5. 设置可访问的 `SITE_URL=https://...`。浏览器通知回执要求 HTTPS；邮件退订链接必须为绝对地址。裸 API 默认不信任转发头；反向代理使用明确 `TRUST_PROXY` IP/CIDR，并清洗客户端转发头。Compose 的 API 不暴露宿主机端口。生产跨域需配置 `CORS_ORIGINS`。
6. 执行 `pnpm --filter @msg/api prisma:deploy` 后构建并启动。新增迁移保留原字段语义；重复的全局事件/模板/抑制名单按最新记录合并，移出的完整行保存在 `MigrationArchive` 表供核查。部分唯一索引由 SQL 迁移管理，不能用 `db push` 替代迁移。
7. 升级后重新登录；旧的无会话版本 JWT 不再有效。检查 `/api/health/live` 与 `/api/health/ready`，后者要求 PostgreSQL、Redis、未暂停的可用 worker。
8. 查看任务列表的 `UNCERTAIN` 和队列失败记录。核实外部发送结果后选择“确认已送达”或明确接受重复风险后重新发送。结果未知不会自动盲目重试。

## 管理功能

- 设置：加密/脱敏配置导出、导入预检、TOTP、撤销登录会话、消息/活动/敏感正文保留策略。0 天表示禁用自动清理。
- 模板：保存草稿、草稿预览、发布、历史版本与回滚；发送只使用已发布内容。缺必填变量在发送前拒绝。
- 定时任务：分页、编辑、暂停/恢复、条件取消、未知结果处理。daily 错过执行后跳到未来执行点，避免集中补发。
- 发送队列：失败/延迟列表、重试、移除；正在执行或结果未知的发送不能被当作普通失败重试。
- 消息：清理预览、投递时间线、服务端已读、邮件兜底单独标记、CSV 公式防护。邮件服务商接受不等于用户阅读。
- 仪表盘：UTC 日统计、数据库聚合、外发成功率、兜底比例、P95 发送/排队延迟、长时间待发送和站内接收。指标按日志尝试统计；失败聚类最多抽样最近2000条，并展示抽样标识。
- 通知中心：短期 SSE 票据、Redis 多实例广播、断线增量分页补拉、状态变化提醒、跨设备已读同步。

## 备份约定

v3 配置包使用稳定 ID，支持同名项目；导入先验证引用和冲突，再以事务落库，重复导入不重复创建任务。包含渠道、项目、绑定、事件、模板草稿和版本、伙伴链接、抑制名单、兜底及安全的运营设置。新增导入定时任务默认暂停。依赖旧消息日志的内部任务明确排除并返回警告。

账号、JWT/TOTP 密钥、消息日志和队列运行状态不在配置包中。项目 API Key 导入后需要重新生成并更新接入方。脱敏包用于检查，不能恢复；加密包使用密码认证加密，密码遗失无法恢复。

旧 v2 按名称关联的备份不自动导入，避免同名实体混合。升级前保留完整数据库；在原实例升级后重新导出 v3。只有 v2 文件时，需先人工消除重名与引用歧义后进行受控转换，不能把 v2 版本号直接改成3。

## 对接补充

- `GET /api/openapi/schema`：项目推送/邮件入口的 OpenAPI 3.0 规范（并非全部管理接口）。
- `POST /api/webhook/dry-run`：使用 `X-API-Key`，预览推送模板、渠道及静默规则，不发送、不占邮件额度；仍受请求限流。
- `POST /api/admin/messages/batch-preview`：逐项校验、渠道去重、预计首次发送次数及 UTC 邮件配额快照；批量发送界面会先预检再确认，修改表单使旧预检失效。配额快照只作参考，最终额度以发送时原子预占为准。dry-run 暂不支持 event，传入会明确400拒绝。
- 重试同一业务使用相同 `Idempotency-Key`；完成后同键返回缓存结果，处理中返回409。不同正文必须换新键。未完成的幂等占用保留以避免超时后重复发送，不能靠等 TTL 规避未知结果。
- 邮件配额以 UTC 日、实际预占发送尝试计数；失败尝试也占额度。PostgreSQL 原子预占，避免并发穿透。
- `unreadEmailFallbackMinutes` 是明确的分钟别名；旧 `unreadEmailFallbackHours` 历史上也一直按分钟处理，升级不改变旧数值。
- `POST /api/admin/schedules/:id/resolve`：`{action:"delivered"}` 或 `{action:"retry",acknowledgeDuplicateRisk:true}`；仅对 UNCERTAIN 条件生效。
- 普通请求体上限256KB；备份接口在验证管理会话后允许20MB。出站 HTTP 使用已校验的解析地址，拒绝重定向并限制响应大小。

## BrowserShell

通知到达时固定回执平台地址；回执采用跨进程文件锁与持久队列，离线/失败后重试，重复回执去重。禁止重定向，校验 HTTPS 根地址、JSON 成功结果和响应大小。界面区分本机已阅读和服务端已同步。旧历史中没有保存平台来源的消息只能使用现有配置地址。
