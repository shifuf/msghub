# 消息推送平台 · 对接开发文档

> 开放接口（Bearer 项目 API Key）：  
> - `POST /api/webhook` / `/api/bark` / `/api/gotify` → **项目策略派发**  
> - `POST /api/email` → **指定收件人 SMTP**（评论回邮等）  
> - `POST /api/bounce` → 退信入抑制名单  
> - `GET/POST /api/public/unsubscribe*` → 公开退订

生产：`https://notify.example.com`

---

## 1. 项目策略（管理员通知）

```bash
curl -X POST "https://notify.example.com/api/webhook" \
  -H "Authorization: Bearer msg_xxx" \
  -H "Idempotency-Key: optional-unique-id" \
  -H "Content-Type: application/json" \
  -d '{"title":"新评论","content":"...","priority":"normal"}'
```

| 字段 | 说明 |
|------|------|
| title / content / html | 正文 |
| priority | `low` / `normal` / `high` / `critical`（默认 normal） |
| event | 事件 code，走事件目录模板/默认优先级 |
| pushTemplate + variables | 推送模板 |
| dedupeKey / Header `Idempotency-Key` | 幂等键，TTL 见项目配置（默认 30 分钟） |

派发顺序：

1. **静默时段**（项目开启且 priority 为 low/normal）：立即站内 + 早晨补发外发
2. 项目已启用**外发推送**渠道（priority 熔断）
3. 失败/无外发 → **SMTP 到管理员邮箱**（项目 `adminEmail` → 全局 `globalAdminEmail`）
4. 再失败/无邮箱 → **站内**

`high` / `critical` **始终立即外发**，不受静默限制。

评论「有回复时发邮件」**不要**走 webhook 策略；应使用下面的 `/api/email` 并传入用户邮箱。

## 2. 事件目录

```bash
curl -X POST "https://notify.example.com/api/webhook" \
  -H "Authorization: Bearer msg_xxx" \
  -H "Content-Type: application/json" \
  -d '{"event":"deploy.done","variables":{"env":"prod","version":"v1.5.0"}}'
```

系统预置：`comment.reply` / `login.fail` / `deploy.done`。可在后台「事件目录」自定义，绑定推送/邮件模板与默认优先级。

## 3. 指定邮箱（评论回邮）

```bash
curl -X POST "https://notify.example.com/api/email" \
  -H "Authorization: Bearer msg_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "user@example.com",
    "subject": "您的评论有新回复",
    "content": "有人回复了您的评论：..."
  }'
```

| 字段 | 必填 | 说明 |
|------|------|------|
| to | 是 | 收件人；须为合法邮箱格式，否则 400 |
| subject / title | 建议 | 主题 |
| content / html | 二选一 | 正文（有 `html` 时优先渲染 HTML） |
| template + variables | 可选 | 邮件模板；缺核心变量会 400 |
| event | 可选 | 事件目录 |
| priority / dedupeKey | 可选 | 同 webhook |

项目需绑定启用 **SMTP** 渠道。渲染时会自动注入 `unsubscribeUrl`（若未传入）。

### 发送失败告警

- SMTP / 推送**最终失败**时，会向项目的**备用渠道**（`isBackup`，或非默认最高优先级外发）推送告警文案。
- 告警**永不走 SMTP**（SMTP 可能已挂），请绑定 Bark / Gotify / 钉钉 / 飞书 / Discord 等即时渠道。
- 支持告警冷却、每日配额、连续失败自动拉黑、幂等、项目级入站限流。
- 管理后台「发送记录」可按收件人 / 仅 SMTP 失败筛选，并**批量重发**；详情可见重试时间线。
- 抑制名单：`/app/suppress`；开放接口 `POST /api/bounce` 可写入退信地址。

推荐模板 `comment_reply`（变量：siteName/articleTitle/actorName/parentSnippet*/replySnippet*/viewUrl/unsubscribeUrl）。

另有博客场景模板（`seedDefaults` 会写入全局）：

| code | 名称 | 主要变量 |
|------|------|----------|
| `comment_reply` | 评论回复 | siteName, articleTitle, actorName, parentSnippet*, replySnippet*, viewUrl, unsubscribeUrl |
| `new_article` | 新文订阅 | siteName/appName, articleTitle/title, viewUrl/url, body, actionUrl, unsubscribeUrl |
| `friend_link_review` | 友链审核 | siteName, friendName, friendUrl, approved, statusText, viewUrl, title, body, actionUrl |

```bash
# 列出可选模板（博客后台选择器用）
curl "https://notify.example.com/api/templates" \
  -H "Authorization: Bearer msg_xxx"
```

## 4. 退订

邮件中的 `unsubscribeUrl` 指向：

- 页面：`GET /unsubscribe?token=...`
- API 预览：`GET /api/public/unsubscribe/preview?token=...`
- API 确认：`POST /api/public/unsubscribe` body `{ "token": "..." }`

token 为 HMAC 签名（`UNSUBSCRIBE_SECRET` 或 `JWT_SECRET`），含 email/projectId/过期时间。

---

## 5. Bark / Gotify 入站

与 webhook 相同鉴权与派发策略；body 字段兼容各自协议（`body` / `message` 等）。同样支持 `priority`/`event`/`Idempotency-Key`。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/webhook` | 项目策略 / 事件 |
| POST | `/api/bark` | 项目策略（Bark 体） |
| POST | `/api/gotify` | 项目策略（Gotify 体） |

| GET | `/api/templates` | 列出项目可用邮件模板（项目 + 全局启用） |

### 管理端新增（JWT）

- 多 Key：`/admin/projects/:id/keys`
- 模拟发送：`POST /admin/projects/:id/simulate-send`
- 入站错误：`GET /admin/projects/:id/inbound-errors`
- 渠道健康：`GET /admin/channels/health`、`POST .../probe`
- 队列：`/admin/queue/stats|failed|...`
- 失败聚类：`GET /admin/dashboard/error-clusters`
- 收件人时间线：`GET /admin/recipients/timeline`

## 7. 渠道类型

INBOX / BARK / GOTIFY / SERVERCHAN / PUSHPLUS / DINGTALK / TELEGRAM / WEBHOOK / SMTP / **FEISHU** / **DISCORD** / **JPUSH**

### JPUSH（极光 · 棱镜浏览器）

后台「渠道管理」新增类型 **极光推送**，配置：

| 字段 | 说明 |
|------|------|
| appKey / masterSecret | 极光控制台凭证（仅服务端） |
| audienceMode | `registration_id`（默认）/ `alias` / `all` |
| registrationId | 棱镜 App 设置 → 推送 → 复制 RID；可多条逗号分隔 |
| timeToLive | 离线保留秒数，默认 86400 |

推送 extras 自动带 `messageId`、`readToken`。客户端点击通知后应调用：

```bash
curl -X POST "https://notify.example.com/api/public/messages/mark-read" \
  -H "Content-Type: application/json" \
  -d '{"messageId":"...","token":"..."}'
```

### 未读邮件兜底

项目详情可开启 **未读邮件兜底**：

- 开关 `unreadEmailFallbackEnabled`
- 等待分钟 `unreadEmailFallbackMinutes`（默认 24 分钟）；兼容旧字段 `unreadEmailFallbackHours`，历史字段虽然名称含 Hours，数值一直按分钟处理，升级不乘以60。
- 邮件模板 `unreadEmailTemplateCode`（空=纯文本；可按项目单独设）

流程：外发推送成功 → 创建定时任务 → 到期时若 `readAt` 仍为空 → SMTP 发管理员邮箱（项目 `adminEmail` → 全局）。已读会取消该定时任务。

Webhook 出站可选 `hmacSecret`：签名串 `timestamp + '.' + body`，头 `X-Timestamp` + `X-Signature-256`（可配）。

### 安全说明（运维必读）

- **JWT_SECRET / UNSUBSCRIBE_SECRET**：生产必须配置 ≥16 位强随机串；弱默认会拒绝退订签发/验签。
- **PUBLIC_BASE_URL**：邮件模板自动注入 `unsubscribeUrl` 时需要。
- **出站 SSRF**：Webhook/飞书/Discord/钉钉 发送前校验 HTTPS + 主机名黑名单 + **DNS 解析后私网 IP**；禁止 302 跟随。Bark/Gotify 自建默认可局域网。
- **幂等**：相同 `Idempotency-Key` 并发第二次返回 **409**（处理中），完成后回放缓存结果。
- **项目限流**：配置了 `rateLimitPerMin` 后，Redis 故障时 fail-closed（拒绝），避免刷爆渠道。
- **备份导入**：渠道 config 会跑 `validateConfig`，非法配置跳过并计入 `channels.skipped`。
