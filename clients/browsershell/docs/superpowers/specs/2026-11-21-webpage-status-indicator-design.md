# 网页连接状态灯设计

## Intent

在 Prism 地址栏的浏览器工具栏中显示当前网页的 HTTPS 连接、未加密 HTTP 连接或主页面加载故障，让用户能发现错误、看懂状态并直接重试。

## Goals

- HTTPS 页面加载完成显示绿色状态灯，HTTP 页面显示琥珀色提示；导航中显示中性状态。
- 主页面网络错误、TLS 证书错误及 HTTP 4xx/5xx 显示相应提示，点击可查看中文说明并重试失败页面。
- 只有当前 WebView 的主页面事件可以改变该页面状态，各标签在切换时还原各自状态。
- 维持现有地址栏、主页沉浸布局和编辑网址交互。

## Non-goals

- 不显示 CSS、图片、脚本等子资源失败；不拦截网页、忽略证书错误或改变系统 WebView 的原生错误页面。
- 不添加第三方依赖、采集或上传浏览记录、或者改变当前 HTTPS/HTTP 导航策略。
- 不声称 HTTPS 可以保证网页本身可信。

## Approaches

- 地址栏内新增可访问的网页连接状态灯；它可在窄窗口中与标题省略共存，和网址栏一起隐藏时尊重主页沉浸模式。选用此方案。
- 在 WebView 内容上方覆盖状态提示：会遮挡网页和增加生命周期/多标签耦合，因此不采用。
- 只靠 Toast 或加载失败页面：提示短暂或无重试入口，不满足用户要求的持续错误提示。

## Architecture and constraints

由 BrowserController 将 HTTPS、HTTP、主页面网络错误、TLS 证书错误及主页面 HTTP 响应错误归一成一条状态回调。浏览器界面根据这条状态更新地址栏指示灯与说明/重试操作；TabManager 按 WebView 所属标签保存运行时状态，切换时复原。HTTP 4xx 显示琥珀提示，HTTP 5xx、证书与网络错误显示红色错误；子资源回调忽略。

按 WebView 主页面标志及当前 URL 核对异步事件，忽略过期导航回调；正确处理重定向和 HTTP 错误回调在页面结束回调后到达的顺序。证书错误必须取消 WebView 请求。网址编辑、暗色主题、没有标签时及 home.local / about:home 均必须无多余灯标。

实现沿用项目 Kotlin/XML、主题色、HTTP 通知方式及 JUnit。认证产品和签名密钥不需要修改；不打包、签名、发布 APK 或修改外部服务。

## Acceptance

自动化测试证明 HTTPS/HTTP/主页、4xx/5xx、证书和网络故障分类正确，且子资源和已被新导航替代的事件不改变当前页。Android Kotlin 编译、全单元测试、debug APK 编译及 lint 检查通过；如果没有已连接设备，则记录这一验证限制而不声称做过界面验收。
